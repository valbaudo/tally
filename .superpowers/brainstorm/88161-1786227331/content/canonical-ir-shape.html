Hierarchical dataflow

Scopes stay visible in canonical IR. Each scope owns a child graph or runtime template. Journal paths mirror the structure.

Strengths

  • Map and loop instances have a natural home
  • Call boundaries and cleanup remain explicit
  • Trace and replay share one path vocabulary

Cost

  • Runtime walks nested graph templates
  • Not a conventional flat DAG scheduler
B
clone→ recon→ static validate[*] cleanup
Runtime expansion problem

The compiler cannot create validate[item-42] before the upstream list exists. It must mutate the graph later or hide a nested program inside a synthetic coordinator node.

Fully flattened DAG

Every executable unit is presented as a peer node. Scopes disappear into synthetic edges and coordinator nodes.

Strengths

  • Familiar scheduler shape
  • Static nodes are easy to topologically sort

Cost

  • Dynamic work requires graph mutation
  • Call, loop, and cleanup boundaries must be reconstructed
  • Author structure and replay structure drift apart
The precise decision

May the canonical IR retain structured scope nodes and child templates, or must compilation erase all hierarchy into one flat list?
