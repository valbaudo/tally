What identifies one piece of work?

The identity model decides whether Dawn can resume precisely, reuse expensive agent work after edits, and repeat side effects without accidental duplication.

Recommended model: identity is layered, not overloaded
Runtime address
Where is it?
run + branch/map/loop path
＋
Work fingerprint
What will it do?
operation + exact inputs + behavior
＋
Attempt
Which try?
1, 2, 3… for diagnostics
＋
Effect key
Same logical effect
stable across retry/restart
Continue finds committed work by runtime address. Derive can reuse a moved or renamed node by matching the work it actually performs. Intentional duplicate nodes remain separate executions because their addresses are distinct.

Choose the foundation

A

Layered identity Recommended

Separate address, reusable-work fingerprint, attempt, and effect key. Preserves precise continuation, broad derivation reuse, intentional duplicates, and safe retry semantics without burdening workflow authors with knobs.

B

Address is identity

Very simple, but moving or renaming a node destroys reuse even when its operation and inputs are unchanged. Derivation becomes much less valuable.

C

Fingerprint is identity

Maximizes deduplication, but identical-looking nodes may represent two intentional executions. It can collapse work that should happen twice, especially external effects.

This is an internal runtime model. Workflow authors do not name or manage these identities.
