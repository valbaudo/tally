## Problem Statement

Every team building a multi-stage agentic product in IT and security writes its own
harness first. Cloudflare wrote VDH. Microsoft wrote MDASH. CodeRabbit, Greptile, XBOW,
Horizon3 each have one. The harness is the part that sequences stages, isolates the
agent, decides whether a stage's work was real, carries artifacts forward, survives a
crash, and bounds spend — and it is rebuilt from scratch every time, by people whose
actual product is something else.

The rebuild is not just wasted weeks. It fails quietly. Measured in dawn itself, by an
adversarial review of its own source (2,859 lines, 1,260 excluding comments):

- **three of four gates were forgeable** — `import sys; sys.exit(0)` scored a pass, and
  the first repair for one of them was forged the same afternoon;
- **a fan declared 3 wide was silently 1**, because image sizing ran before the image
  was pulled and cached the failure for the process;
- **a resumed timeout came back `infra_error`**, the one state that retries, so the run
  re-dispatched into the same wall and rewrote its own receipt to say so.

None of these surfaced as errors. Each looked like a working pipeline.

## Demand Evidence

**Weak, and stated plainly: n=1.**

- The founder is the one confirmed user, with direct scars from building VDH and MDASH
  protocols on dawn.
- Cloudflare's and Microsoft's engineers are *inferred* cases from published write-ups.
  Nobody has spoken to them. They may have enjoyed building their harness, shipped in
  three weeks, and never thought about it again.
- No one has asked for dawn, tried to install it, or described this pain unprompted.

This is the binding constraint on everything below. It is not an architecture problem
and no amount of design fixes it.

## Status Quo

Three real alternatives, all in use today:

| What | Who uses it | What it costs |
|---|---|---|
| Bespoke harness | Cloudflare, Microsoft, and the founder | Weeks of build, then silent failure modes nobody sees without reading the code |
| Harbor directly | Benchmark and eval teams; NVIDIA NeMo ships a runner | Runs *one* task well: container, agent adapters, verifier-emits-reward. Sequencing many is yours to write |
| Temporal / LangGraph + glue | Teams that need durability or a graph | Durable multi-step and sandboxed agents (Temporal × OpenAI Agents SDK, GA March 2026), but **no verifier concept at all** — the composition is still yours to write |

**Sourcing, applied evenly.** Exactly one claim in this table is backed by primary
research in the repo: Harbor 0.22.0, in three `docs/research/harbor-*.md` documents citing
installed source paths and line numbers. The other three — "NVIDIA NeMo ships a runner",
"Temporal × OpenAI Agents SDK, GA March 2026", and the founder's own assessment that
making dawn's shape work inside LangGraph would amount to writing dawn again — rest on a
single web search or on memory, and none has a primary source here. All three are
load-bearing for positioning. All three need one.

## Target User & Narrowest Wedge

**Domain:** IT and security agentic workflows — static analysis, agentic pentesting, PR
correction (CodeRabbit-shaped), code review.

**User:** the engineer inside a team whose product is one of those, who is currently
maintaining a harness that is not the product.

**Wedge:** the mechasuit, not the examples. dawn does not compete with CodeRabbit or
XBOW; it is the thing each of them built twice. Arms dealer, not combatant.

**Not yet answered:** a specific human with a name. The founder chose himself (n=1) plus
the inferred Cloudflare/Microsoft engineers. That gap is what The Assignment attacks.

## Constraints

- **Zero marginal model spend.** Development runs only on OAuth subscriptions already on
  the founder's laptop (Claude Code, Codex). No metered API keys.
- **No fallbacks, no legacy paths.** A fallback is treated as evidence the design is
  wrong one level up.
- **Simple, straightforward, elegant** outranks completeness and defensive coverage.
- **Primary sources only**; a negative result is a result.
- dawn currently has **no distribution** — not published as a Go module, not tagged, not
  installable by anyone.

## Premises

1. **The orchestration primitives are commoditized.** Harbor does container + agent
   adapters + verifier-emits-reward. Temporal does durable multi-step with sandboxed
   agents. dawn's value cannot be "we orchestrate." *(accepted)*
2. **The unoccupied position is the composition:** multi-stage, per-stage isolated
   verification where only a sound gate reaches success, plus artifact transport, resume,
   and spend limits. Nobody ships the combination. *(accepted)*
3. **Demand is n=1 plus two inferred cases never spoken to.** *(accepted)*
4. ~~The gate is the differentiator.~~ **Rejected, and then answered.** *(resolved)*
   The founder held the gate is a component, not the pitch; the facilitator held it was
   the only thing not already shipped by someone else. Both were circling the same
   object from different sides. The resolution is premise 6.
5. **"Build agent workflows easily" is a loud, mostly-free category.** A paid product
   needs a reason that is not ergonomics. *(accepted)*
6. **The differentiator is Harbor-as-the-unit-of-work, composed across vendors.**
   *(accepted — the founder's answer, stated three times before it was heard)*

   Two halves, both checkable:

   - **The unit of work has a verifier inside it.** A dawn stage is one Harbor trial:
     isolated container, one agent CLI, and a verdict from a verifier in a SEPARATE
     container. LangGraph's unit is a function; Temporal's is an activity. Neither has a
     unit of work that can be wrong about its own success. Both can shell out to
     `harbor run` — and then the task.toml generation, artifact transport, verdict-to-state
     mapping, digest pinning and receipts are yours to write. That is dawn, written again.
   - **Multi-vendor composition is a correctness property, not a feature.** dawn holds
     per-vendor facts the runtime enforces: `Codex.fanOut` is false because its OAuth
     refresh token is single-use and a fan would log the operator out of their own
     machine; `ClaudeCode` fans; the semaphore is keyed per agent name so the cap holds
     structurally rather than by convention. No other framework models "this vendor
     cannot fan out" as something it enforces.

   The gate is not a separate pitch. It is what makes the unit of work worth having.

## Approaches Considered

### Approach A: Second domain, one real user
Publish the module; build one protocol outside security for one named person who agreed
in advance to use it. Effort: S (human: ~1 week / CC: ~1 day). Risk: Low. Attacks n=1 directly.
**Rejected in session:** too narrow for what the founder is building.

### Approach B: Runner-agnostic protocol layer
Decouple from Harbor so runners plug in (Harbor, Temporal, raw Docker).
Effort: L (human: ~6 weeks / CC: ~4 days). Risk: High.
**Rejected in session:** designing universality from one domain's experience bakes VDH's
shape into the API and calls it general. Premature at one user.

### Approach C: Ship it and instrument for the wedge
Publish openly, lead with the forgery write-ups, let usage name the wedge.
Effort: M (human: ~2 weeks / CC: ~1 day). Risk: Medium.
**Deferred, not rejected:** stronger after the IT protocols exist as evidence.

### Approach D: Earn genericity across the IT domain — **RECOMMENDED, conditional**
Effort: M (human: ~3 weeks / CC: ~2 days). Risk: Medium.

**The net-new scope is smaller than it first looks.** `protocols/` already holds five:
`cybergym`, `mdash`, `prci`, `vdh`, `vdhadyen`. **`prci` IS the PR-correction protocol**
— 13 recorded runs — and `vdh`/`vdhadyen` already cover agentic pentesting. So of the
three shapes named in session, only **code review** is genuinely new; a second candidate
would be static analysis, which is closer to `cybergym` than it looks.

So D is one, maybe two new protocols — not three. Where the API bends building them is
where it was overfit to vulnerability hunting, and the bends are the specification.

The hard part is not Go plumbing. In every existing protocol the expensive part was the
gate oracle (mdash's forged-ceiling rewrite, vdh-adyen's live gate) and each took days of
iteration. A code-review gate — deciding whether a review was *correct* rather than
merely well-formed — has no template here to copy and is the real cost of D.

### Approach E: The wrapper UI
A view over a running protocol: stages, fan, live state, gate verdicts, spend.
Effort: M (human: ~3 weeks / CC: ~2 days). Risk: Medium.
**Deferred:** it is what makes dawn demoable and legible to anyone who is not reading Go,
but a UI over one user's library is a shell around an unanswered question. Right after D.

## Recommended Approach

**The Assignment first. Then D, scoped to IT and security, conditional on its result.**

These are sequenced, not alternatives, and an earlier draft of this document contradicted
itself by recommending D while The Assignment opened with "not go build it." The order is:

1. **The Assignment (this week).** It costs a day and attacks n=1, which is the binding
   constraint. Nothing D produces is worth more than knowing whether anyone wants it.
2. **Then D (≈3 weeks), IF the assignment returns any signal at all** — even one engineer
   saying "yes, our harness has this problem." D is how genericity stops being an
   aspiration, but building it against n=1 is the failure mode this session exists to
   avoid.

**Kill criterion, stated in advance:** if five outreach attempts produce zero engaged
replies, do not start D. Either publish (Approach C) and let the writing find people, or
accept that dawn is excellent personal infrastructure — which is a real outcome, not a
failure.

Why D and not B, when the assignment does come back positive: the founder's own precedent.
He built three VDH stages and called it VDH; the objective needed eight with two loops.
The same error at the API level — designing "generic" from one domain's experience —
produces a framework shaped like vulnerability hunting with "generic" written on it.

## Open Questions

1. **Is Harbor a dependency or a competitor?** dawn is 1,260 lines of code over a runner
   that already does containers, adapters, and per-task verification. If Harbor grows
   multi-stage sequencing, what is left? Unanswered, and it decides the moat.
   **Checkpoint:** read Harbor's changelog and open issues before starting D, and again
   at D's midpoint. Multi-stage sequencing appearing upstream is a stop-and-rethink, not
   a feature to race — it collapses premise 2, on which the whole moat now rests.
2. ~~What is the differentiator, if not the gate?~~ **Answered — see premise 6.**
   Harbor as the unit of work, composed across vendors. The remaining risk is not that
   the answer is vague; it is that the answer is a composition over a dependency, which
   makes Open Question 1 the load-bearing one.
3. **Does anyone building an agentic IT product want to outsource their harness?** Teams
   whose product *is* the pipeline may consider the harness core IP rather than overhead.
4. **Is the LangGraph conclusion true?** Load-bearing for positioning, remembered from a
   prior session, written down nowhere.

## Distribution Plan

**What already exists** (an earlier draft of this document got both of these wrong):

- `.github/workflows/ci.yml` runs `go build`, `go test -race`, and `go vet` on an
  ubuntu + macos matrix. The Docker-dependent tests skip themselves rather than fail, so
  CI honestly covers the pure logic and says nothing about the container paths.
- `README.md` already has a four-step "Running a protocol from a clean checkout".

**What is actually missing, and it is more than a tag.** `go get` resolving the module
does NOT make a protocol runnable by a stranger. A new user needs, today, all of:

| Gap | Why it blocks | Fix |
|---|---|---|
| No semver tag | `go get` has no version to resolve | Tag `v0.1.0`; Go needs no registry push |
| Images are local-only | Every protocol pins a digest built by `docker-bake.hcl` and re-pinned by `./repin`, and those images exist on one laptop | Push to GHCR, and teach `repin` to push — it does not today |
| No release job | CI tests but never publishes | Add a tag-triggered job; it needs GHCR registry credentials as repo secrets |
| Harbor 0.22.0 | A separate Python/uv tool dawn shells out to | Document the version pin; it is already a hard dependency |
| Docker or OrbStack | Every stage and every gate is a container | Prerequisite, not fixable |
| An agent credential | README step 3 mints a Claude Code OAuth token via `claude setup-token`, explicitly not automated | Cannot be shipped; each user brings their own subscription |

The last two are the real distribution ceiling: dawn is not installable software so much
as a thing you assemble. That is worth stating plainly before "publish it" appears on any
roadmap.

**Load-bearing finding.** Harbor 0.22.0 — the pinned dependency — already ships
multi-stage sequencing. `trial/multi_step.py` defines `MultiStepTrial`; `StepConfig`
(`models/task/config.py:759`) carries a per-step verifier, `min_reward` ("abort remaining
steps"), and per-step artifacts into `steps/{name}/artifacts/`; and
`models/task/verifier_mode.py:31-64` resolves a SEPARATE verifier image on ANY step, not
only the last. Premise 2's "nobody ships the combination" is substantially false: the
dependency ships four of the five parts. Open Question 1's checkpoint fired before D
started, which by this document's own rule is a stop-and-rethink.

**What survives, verified against source.** Multi-vendor across stages (`trial.py:967`
builds `self.agent` once per trial; `StepConfig.agent` carries only timeout, user and
network policy — no vendor field); a runtime-computed stage graph (dawn protocols are Go
programs with loops, Harbor's `steps` is a static TOML list); resume across process
restarts; actuation; the six-state model. Premise 6's second half is now the whole
differentiator rather than half of one — and no protocol exercises it: all five use
`dawn.ClaudeCode`, `dawn.Codex` appears in none, and codex has never authenticated inside
a dawn run.

**Decisions taken in review.** Translate `vdh` end to end (all 8 stages) into a Harbor
`[[steps]]` task.toml, unboxed, with no kill criterion. Fold a Codex stage in at
`validate` — the adversarial stage that produced 9 verdicts, 9 "confirmed", 0 refutations
across two measured runs — so one experiment yields both the Harbor comparison and the
first multi-vendor evidence. Run The Assignment in parallel rather than before or after.
Verify codex auth by hand-running the pinned image once, rather than adding a preflight.

**CROSS-MODEL:** outside voice ran as a Claude subagent (Codex CLI unusable:
`~/.codex/config.toml` pins `model = "gpt-6-astra"`, rejected by the account). It caught a
real risk this review missed — `docs/research/oauth-cli-in-container.md:154` says Codex
"must not be fanned out", and `validate` is a fan. Its date was stale: the recorded
`exp` of 2026-09-07 was measured on 2026-09-04 and the laptop has auto-refreshed since.
Re-measured 2026-09-07: `exp 2026-09-17T07:58:02Z`, 234.7h out, window open. A ~16-minute
vdh run cannot straddle it. Re-measure before every run; the recorded date is never the
live one.
