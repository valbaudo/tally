01 / Executive answer

Preserve the nucleus. Replace the assumptions.

Dawn already owns the hardest invariants: strict plans, independent judges, accepted-attempt-only commits, content-addressed state, and rerun-as-resume. It should add composition around Invocation → Backend → Result, not inflate that seam.

04 / The target language

Five semantic ideas. Everything else lowers into them.

This is deliberately smaller than AWF. BM25 is a library. Docker is a process dependency. A jury is sugar. Static parallelism is discovered from data.

01

Contract

Typed workflow and leaf inputs/outputs: canonical JSON values plus named artifacts.

02

Leaf

An agent or native script executes one task and returns the same result envelope.

03

Composition

Typed calls, bounded conditions, keyed map/reduce, and scoped try/finally.

04

Acceptance

Generate, independently evaluate, repair from typed feedback, commit one attempt.

05

Policy

Retry, timeout, cache, idempotency, secrets, resource pools, and failure handling.

Script boundary: give every process DAWN_INPUT (canonical JSON), DAWN_OUTPUT (schema-validated JSON), DAWN_FILES (named artifacts), and DAWN_IDEMPOTENCY_KEY. Do not interpolate runtime strings into shell source.

05 / Deep-module architecture

One compiler. One interpreter. Two leaf executors.

Sub-workflows compile into hierarchical addresses in the same canonical IR. The interpreter remains the only writer of durable state; workers return candidates.

06 / Product discipline

The cut list protects the promise.

Build into Dawn

  • First-class values, files, trees, and assets
  • Native process execution
  • Local typed calls and canonical IR
  • Keyed map/reduce and bounded conditions
  • General gates; current jury as shorthand
  • Retry/effect/finally policy
  • Adapter roles, skills, BM25, trace

Keep outside Dawn

  • Docker or DinD lifecycle language
  • PDF/image/document-specific nodes
  • Unrestricted text templating
  • Arbitrary expressions or embedded code
  • Explicit static parallel syntax
  • A separate LLM-judge engine
  • Global mutable workspace semantics

07 / Delivery sequence

Each milestone ends in a vertical proof.

M1

General leaf contract

Values/artifacts, workflow contracts, native process runner, adapter registry, roles, environment-name allowlist. Prove script → agent → named report with correct reuse.

M2

Composition

Local calls, bounded when, keyed map, partial-success policy, script/quorum reduce. Prove the Prestige static hunt phase and resume by item key.

M3

Trust and failure

General gates, retry versus repair, filtered catch/finally, cache/effect/idempotency. Prove one full Prestige validation item with a 3-agent panel and deterministic aggregate.

M4

Skills and operation

Asset snapshots, router interface, BM25, hierarchical traces, resource pools, then persistent sessions and durable prune only when earned. Prove killed-run recovery of the full pipeline.

08 / Steve Jobs design review

Simple today. Not yet simple at the larger promise.

Verdict6NOT DONE / 10
The One Thing

Turn a typed workflow into accepted, resumable artifacts, independent of the native agent or script that produced them.

Keeps its promise?

The narrow static-agent-DAG promise: yes. The general native-workflow promise: no—Prestige requires scripts, calls, dynamic fan-out, richer gates, artifacts, and effects.

Fix list

Contracts, native leaves, typed calls, keyed map/reduce, general gates, explicit failure/effect policy, roles, skills, BM25, hierarchical state.

Back of fence

The current explainer is visually strong, but its saved wrapper is heavy and mobile rendering forces/clips wide content. In code, the equivalent hidden debt is field-name-based workspace handling and string-only values spread across parsing, binding, schema, preflight, and CLI behavior.

Software-design score: 6.3/10. The backend and store are deep seams; package purposes and abstraction comments are excellent. The failed/partial diagnostics are change isolation around the value/artifact model, a plan package spanning too many decisions, and no evidenced ADR/strategic-design record for the broader product. The fixes are the canonical IR, first-class result contract, and explicit dynamic-address/effect decisions before feature implementation.

Conclusion

Dawn should not become “AWF without Docker.”

It should become the smaller language Prestige proves is necessary: typed contracts + native leaves + composition + acceptance + policy. Scripts make the work open-ended. Artifacts make files first-class. Gates make stochastic work trustworthy. The journal makes all of it resumable.
