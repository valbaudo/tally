# pr-ci (toy)

The target for the protocol that MUTATES something: a real git repo with a
deliberately failing test, and a one-command CI check with a clear exit
code. Pass condition: the check goes from red (non-zero) to green (zero)
after a real commit.

## Why `repo/` isn't committed here

`repo/` is generated by `init_repo.sh` and is a genuine nested git
repository (its own `.git`, its own commit history) -- that's the actual
deliverable an agent would be pointed at. It's gitignored rather than
committed into tally's own history, the same way `experiments/harbor/jobs/`
is: regenerate it on demand from the tracked source (`seed/`, `fix.patch`,
`init_repo.sh`) instead of carrying a nested `.git` inside this one.

## What it is

```
seed/calc.py       average(nums) -- has one seeded bug (a stray "- 1")
seed/test_calc.py  two unittest cases that fail against the bug
seed/ci.sh         the CI check: `python3 -m unittest -v test_calc.py`, one command, exit 0/1
fix.patch          a real diff that removes the bug (the "PR")
init_repo.sh        regenerates ./repo: git init, real commits, RED state
verify.sh           the full demonstration: init -> red -> apply fix as a real commit -> green
```

## How to check it

```bash
cd experiments/targets/pr-ci
./init_repo.sh          # (re)creates ./repo, 2 real commits, ends RED
(cd repo && ./ci.sh)    # the CI check an agent/harness runs -- exit 1, tests fail
```

To prove the pass condition is reachable via a real mutation (this is what
an agent's PR would do, played here by applying `fix.patch` as a commit):

```bash
./verify.sh              # init, confirm red, apply fix.patch as a commit, confirm green
```

`verify.sh` exits 0 only if the check was red before the commit and green
after; anything else (e.g. `fix.patch` fails to apply, or the test suite is
green from the start, which would mean the target doesn't actually test
anything) is FAIL, exit 1.

## Pass / fail condition

- **Fail (as shipped)**: `repo/ci.sh` exits 1, two `AssertionError`s (`4.0 != 5`, `1.0 != 2`) -- `average()` subtracts 1 it shouldn't.
- **Pass (after the mutation)**: `repo/ci.sh` exits 0, both tests `ok` -- after `git apply fix.patch` (or the equivalent one-line fix) is committed.

## Pinned

Python 3.14.7 (stdlib `unittest` only), git 2.55.0. No network, no CI
provider -- `ci.sh` is the entire check, runnable anywhere `python3` and
`git` exist.
